# THU-BDC2026 Agent Handoff

## Current Goal

This repository is for the THU-BDC2026 stock prediction competition. The user wants a weekly strategy that can find 5 genuinely strong stocks for the next 5 trading days, not a near-all-in Top1 bet. The target is roughly 10% average weekly return because that may be needed for a strong ranking.

The current bottleneck is still stable Top5/Top10 recall. The current formal submission is compliant and reproducible, but historical Top5 equal-weight backtests are still far below 10%.

## Current Formal Model

`code/src/train_current_fusion_submission.py` trains three LightGBM ranker profiles and blends date-wise score ranks:

| profile | weight | data |
| --- | ---: | --- |
| `base_rank` | 0.60 | official/local K-line, metadata, market context, no TuShare event tables |
| `event_text_rank` | 0.20 | hot stock, limit, top list, margin, board hot, plus `ths_hot_reason`/`ths_hot_concept` keyword features |
| `event_board_rank` | 0.20 | hot stock, limit, top list, margin, board hot, no event text keywords |

Portfolio layer:

- model score is adjusted by `advanced.decay_risk`: `score = model_score_rank - risk_penalty`
- risk components: `strength_decay_score`, `runup_reversal_score`, `event_proxy_risk`
- default risk penalty weight: `0.02`
- dynamic Top5 weights use confidence gap and decay risk; current output is `0.24,0.22,0.20,0.18,0.16`
- risk filter: `close_strength > 0.25`, `ret_20 > -0.25`, and `total_decay_risk < 0.78`
- industry cap: default `--max-per-industry 2`

This is no longer the previous near-single-stock template.

## Key Findings So Far

The strongest reproducible conclusion is that the model should be judged by Top5 equal-weight quality, not rank1. Recent strict 14-week tests show:

- `no_event` single ranker: Top5 equal return about 4.13%.
- `all_event_text` single ranker: Top5 equal return about 3.30%, best policy about 4.00%.
- Score blend `no_event 0.65 + event_text 0.25 + all 0.10`: Top5 equal return about 4.67%.
- Wider score blend adding board-hot OOF scores found `no_event 0.60 + event_text 0.20 + extra_board 0.20`: Top5 equal return about 4.96%.

This is progress versus the plain all-feature ranker, but it is not solved. It is still far from the user's 10% target.

Strength-decay risk layer results:

- `no_event_decay` 14-week best policy return: about 4.52%, rank1 return about 5.59%, rank1 `>=10%` weeks 5/14.
- `all_decay` 14-week best policy return: about 4.51%, Top5 equal return about 3.55%.
- For the historical `no_event/event_text/extra_board` blend, heavy penalties hurt Top5; the tuned default is `0.02`, not `0.22`.
- With penalty `0.02`, Top5 equal return falls from about 4.96% to 4.28%, but rank1 mean improves from 3.92% to 4.71% and rank1 `>=10%` weeks improve from 3/14 to 4/14. Treat this as risk control, not alpha creation.

An offline TF-IDF + SVD semantic text experiment was added and tested, but it is not used in the formal submission because it hurt Top5 quality:

- `all_semantic_event_text`: Top5 equal return about 1.74%.
- `only_semantic_text`: Top5 equal return about 2.30%.
- Blend search with semantic scores assigned best weight 0.0 to semantic signals; the best remained `no_event 0.60 + event_text 0.20 + extra_board 0.20`.

## Event/Text Feature Work

`advanced.features.FeatureConfig` now has:

- `add_event_state`
- `add_event_text`

Event text features use `ths_hot_reason` and `ths_hot_concept` and encode keyword families for:

- risk/退潮: conflict easing, stop-fire, abnormal volatility, risk, regulation, sell-down, loss, drawdown, etc.
- positive catalysts: earnings growth, order, tender win, production, approval, cooperation, demand, breakthrough, chips, compute, drug.
- themes: geo/shipping, AI/chip, drug, energy.

This was added specifically because pure K-line features cannot see event reversals such as shipping names reacting to Hormuz-related news.

## Tools Added

`code/src/tune_top5_score_blend.py` tunes score blends against the correct objective:

```bash
./.venv/bin/python code/src/tune_top5_score_blend.py \
  --score no_event=model/feature_ablation_recent14_core/no_event/walkforward_scores.csv \
  --score event_text=model/feature_ablation_recent14_event_text/all_event_text/walkforward_scores.csv \
  --score all=model/feature_ablation_recent14_core/all/walkforward_scores.csv \
  --output model/feature_ablation_recent14_event_text/blend_search_top5_equal_repro.csv \
  --step 0.05
```

It reports mean Top5 equal return, median return, `>=10%` weeks, minimum week return, true Top5/Top10 hits, and predicted Top10 coverage.

`code/src/build_event_semantic_factors.py` builds offline `event_semantic_factors.csv` from THS hot text using Chinese character n-gram TF-IDF and TruncatedSVD. This avoids keyword templates, but current 14-week validation says it should stay experimental.

## Failed Or Weak Directions

- Near-all-in Top1 has high upside but unacceptable concentration risk.
- Simple Top10/10% binary candidate classifiers were weak.
- GPU GRU sequence smoke test was weak.
- CatBoost was runnable but not proven better enough.
- `recall` relevance mode hurt recent smoke tests.
- `burst` relevance was weaker than plain `rank` on 14-week no-event tests.
- Event state recency/decay features alone did not solve recall and can add noise.

## QLib Alpha158/Alpha360 Status

`qlib` is not installed. Older `code/src/utils.py` has Alpha158-style features, and `advanced.features` already covers many Alpha158-like rolling price, volume, volatility, channel, rank, cross-sectional, and industry-relative features.

QLib features should be treated as an ablation candidate, not a guaranteed fix. The core problem appears less like "no Alpha158 features" and more like "event/catalyst data is sparse and weakly aligned with a 5-day Top5 label."

## Recommended Next Work

1. Give each formal profile its own extra-factor directory, so `event_text` can use no-board data while `event_board` uses board-hot data exactly like the OOF search.
2. Cache feature frames during train/predict; current three-profile formal run is slow because it rebuilds wide features repeatedly.
3. Run the Top5 blend tuner over 14-40 weekly cutoffs, not only recent 14 weeks, to test robustness.
4. Search Top5-specific feature families:
   - board hot only
   - event text only as risk veto
   - no industry-relative
   - no valuation/size
   - long-history 2018 data
   - 365-day and 730-day training windows
5. If continuing NLP, prefer supervised or weakly supervised event semantics over unsupervised topics:
   - train text factors directly against future 5-day return buckets
   - use cached local Chinese sentence embeddings only if the model files are committed or otherwise reproducible offline
   - validate with Top5 equal return, not semantic plausibility
6. Continue optimizing for:
   - average Top5 equal return
   - `>=10%` week count
   - average true Top10 hits
   - worst-week drawdown

Do not present the current 4-5% range as a satisfactory solution. It is only a more defensible non-all-in baseline.
